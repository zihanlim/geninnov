## Layers

| Layer | Name | Source | Output |
|-------|------|--------|--------|
| L0 | Macro Ingestion | `backend/data/macro_fetcher.py` | `macro_snapshot` dict (FRED series + yfinance) |
| L1 | Theme Detection | `scripts/daily_refresh.py` → `build_theme_signals` | `theme_signals` table (mention count, sentiment, cross-asset price corr, momentum). The correlation term is measured over **every mapped instrument and collapsed per asset class** ([ADR-0127](docs/adrs/0127-the-cross-asset-term-measured-one-asset.md)) — it previously read whichever ticker Postgres returned first, because the loop's `if not pd.isna(corr)` guard could never fail against a 0.0 sentinel. `correlation_with_mentions` now returns **None** for not-measurable, and `hype_score` renormalises over the remaining components rather than scoring a data gap as zero |
| **L1b** | **Narrative Tracking** | `backend/services/narrative_tracker.py` (orchestrated by `daily_refresh.run_narrative_tracking`) | `market_news` + `narrative_signals` tables. Tracks the **share of voice** of every 1–3-gram in an un-themed corpus, with a robust (median/MAD, floored) velocity against each phrase's own history, and labels each with the anchor theme already covering it ([ADR-0128](docs/adrs/0128-a-theme-we-did-not-name-in-advance.md)). Dependency-free and deterministic, so unlike `theme_discovery.py` it runs daily and in CI. **SHADOW**: nothing here sizes a position or reaches L5 |
| L2 | Factor Exposure | `backend/data/factor_exposures` table | `factor_exposures` dict (FF5 + UMD betas per ticker) |
| L2b | Duration / IG-spread / quality betas per asset (shadow) | `backend/services/credit_rates_exposures.py` | `credit_rates_exposures` table (migrations 060 + 061). Three legs — `d_ust10`/`d_ig`/`d_qual` (DGS10, IG OAS, HY-minus-IG OAS), differenced and expressed in basis points — fitted two ways: `total_beta_*` (three univariate regressions; interpretable, `-beta_ust10` reads as effective duration in years, but double-counts with `beta_mkt` and must never drive a scenario) and `marginal_beta_*` (each leg residualised on FF5+UMD, the three residuals then entering ONE joint fit — orthogonal to the equity block, so `factor_exposures` stays bit-identical, ADR-0093's revision obligation avoided rather than discharged). `status` (`measured`/`insufficient_history`/`degenerate`) travels with every row; betas are NULL, never 0.0, on a failed fit. **Sizes nothing** — `optimizer.py`, `book_metrics.py` and `expected_returns.py` still do not read it — but as of [ADR-0192](docs/adrs/0192-a-fallen-angel-transmits-through-measured-not-hand-set-shocks.md) it is no longer callerless: `scenario_analysis.py`'s `S7_fallen_angel` reads `marginal_beta_ig`/`marginal_beta_qual` (never `total_beta_*`, which double-counts with S7's own `mkt` shock) through a new tier in `_resolve_shock`, fetched once by `q1_agent._load_credit_betas` (`{}` when unmeasured, so S7 degrades to its factor-and-override-only behaviour). Since [ADR-0193](docs/adrs/0193-a-beta-must-clear-its-own-standard-error-before-it-can-stress-the-book.md), migration 061's `marginal_se_ig`/`marginal_se_qual` gate that transmission: a beta only drives S7 when `|beta/se| >= CREDIT_BETA_T_THRESHOLD` (2.0) **per leg** — residualising leaves a small-variance regressor, so the raw coefficient is routinely large and imprecise, and `marginal_r2` (the joint fit's r², dominated by the equity block) cannot police it. A beta that fails the gate falls through to the sector/factor tier, never a fabricated 0.0; a NULL SE (pre-061 row) fails closed the same way. Measured live 2026-07-30: **1 of the 9 held names (GEV) clears the gate — via its quality-gap leg only** (t=+2.33; its own IG leg, t=-1.31, does not), the other 8 held names transmit through no leg at all; across the full 62-asset universe 16 clear on at least one leg, almost all of them literal bond/credit ETFs (LQD, HYG, JNK, ANGL, EMB, AGG, IEF, SHY, BIL) where real spread/duration sensitivity is expected. See [ADR-0190](docs/adrs/0190-credit-rates-exposures-shadow-on-arrival.md) |
| L3 | Regime Classifier | `backend/services/regime_classifier.py` | `regime` dict (cycle + sentiment). Pure function of L0, so it is the one layer that can be rebuilt for past dates — `scripts/backfill_regime.py`. Every input read is bounded by `as_of`, including `_compute_spx_breadth`, which was NOT bounded until the backfill exposed it: it would have stamped today's breadth on every historical row. That same function was also a **boolean wearing a percentage** — SPY above its own MA → 65.0, else 35.0 — which, against sentiment rules of `<40` / `>60`, fired on every resolving day and made `neutral` unreachable ([ADR-0091](docs/adrs/0091-breadth-must-be-a-share-of-something-named.md)). It is now the share of the 11 GICS sector SPDRs above their own 200d MA **Two macro cross-currents (proposed, [ADR-0139](docs/adrs/0139-dollar-debasement-indicator.md) + [ADR-0140](docs/adrs/0140-hawkish-dovish-pivot-indicator.md))** join the regime row: `debasement_pressure` 0-100 with 4 component columns (DFII10 + DX-Y.NYB + GC=F, 26w lookback), and `fed_posture` (hawkish/neutral/dovish) + `fed_pivot_delta` signed -2..+2 (DFF + DGS2 + DGS10, 13w FOMC cadence). ## Data Flow

```
L0: macro_fetcher.py
    → FRED (via python-dotenv) + yfinance
    → macro_snapshot dict

L1: daily_refresh.py / build_theme_signals
    → Brave Search MCP (news) + Reddit PRAW (social)
    → Sentiment scoring (VADER + FinBERT mock)
    → Supabase: theme_signals table

L2: factor_fetcher.py
    → Ken French Data Library (FF5 monthly + UMD monthly)
    → yfinance (252-day return correlations)
    → factor_exposures dict (beta_mkt, beta_smb, beta_hml, beta_rmw, beta_cma, beta_umd, r_squared)

L3: regime_classifier.py
    → macro_snapshot inputs: yield_curve_slope, HY_OAS, VIX, real_rate, SPX breadth
    → cycle: early / mid / late / recession
    → sentiment: risk-on / risk-off

L4: daily_refresh.py / compute_and_persist_risk
    → FRED (SPX total return) + historical portfolio returns
    → VaR (historical, 95%), CVaR, Sharpe, beta, concentration HHI
    → Supabase: portfolio_risk table

L5: q1_agent.py / run_q1_agent
    → L0–L4 outputs (aggregate_context)
    → screen_candidates: filter the L1 pool (lens, R² ≥ 0.10, dedupe, cap) — hype gate + direction + two-sided inherited from L1 (ADR-0030)
    → compute_book_metrics: FF5+UMD tilts, net/gross exposure, cap violations, corr matrix
    → run_scenario_analysis: 7 stress scenarios — 4 risk-off (VIX/rates/USD/credit) + 1 risk-on melt-up, so a net-short book is stressed on both tails (ADR-0074),
                             + 1 supply shock that transmits through SECTOR_MAP rather than market beta, so a position the factor model cannot see is still stressed (ADR-0088)
                             + 1 fallen-angel that transmits through MEASURED credit_rates_exposures betas rather than a hand-set shock (ADR-0192)
    → reason_picks: LLM (MiniMax-M3; Anthropic/Gemini are keyed fallbacks) → top 5 long + top 5 short + thesis + counter-thesis
    → verify_citations: citation guardrail (max 2 retries → fallback)
    → size_positions: HypeScore-weighted $100M allocation + 20%/30%/35% caps
    → Supabase: research_recommendations + research_agent_runs

**L5 is the only stochastic layer in the architecture.** Everything from L0 through L4 is a pure function — no LLM, fully reproducible. The LLM enters only at `reason_picks` and is bounded by:
- A hard candidate-set filter (LLM can only pick names that survived `screen_candidates`)
- The citation guardrail (`verify_citations` → max 2 retries → deterministic fallback)
- The size-positions cap enforcement (single-name 20% / sector 30% / geo 35%)

The LLM is treated as a *constrained synthesizer*, not a free agent. See [ADR-0012](docs/adrs/0012-citation-guardrail-llm-defense.md) and [ADR-0013](docs/adrs/0013-deterministic-stochastic-split.md) for the design rationale.

L6: frontend/app/book/page.tsx
    → Reads research_recommendations from Supabase
    → Renders: per-trade thesis, book view, pool depth, turnover, replication
    → Every numeric claim carries a citation footnote (L7, see ADR-0010)
    (/research, /portfolio and /trades are RETIRED — server redirect() → /book
     since ADR-0025/0040. This line said `frontend/pages/research.tsx`, a path
     that has never existed in the app-router layout.)

L7: frontend/components/{ThemeDerivationDrawer,CitationList,RegimeInputs}.tsx
    → Reads theme_signals_history (raw signals), themes (normalized sub-scores),
      scoring_config (weights), research_agent_runs.citations (LLM output citations)
    → Renders: click-through derivation showing raw signal → normalization →
      weight → final score, with source counts and citation footnotes
    → Pattern adopted from Perplexity Finance: every numeric claim has visible
      provenance (see ADR-0009, ADR-0010, ADR-0011)
```

## Q1 Agent: Citation Guardrail

Every numeric claim in the LLM's output must cite a FRED series ID (e.g. `BAMLH0A0HYM2`) or theme key. `verify_citations` checks each citation against `macro_snapshot`. Un-cited numbers → retry (max 2). On third failure → `fallback_picks` (deterministic, no LLM, always produces output).

The citation infrastructure (research_agent_runs.citations JSONB + verify_citations step) is the data layer that powers the L7 provenance UI — see [ADR-0010](docs/adrs/0010-citation-footnotes-everywhere.md) for the rendering-side design and [ADR-0012](docs/adrs/0012-citation-guardrail-llm-defense.md) for the guardrail design rationale.

## L7: Provenance UI Layer (ADR-0009, 0010, 0011)

The platform's quantitative outputs (HypeScore, TradeScore, regime classification, factor betas) are not auditable from the current UI — they show as numbers without showing how they were derived. To address this, L7 surfaces the full derivation chain from raw data to final number:

- **Theme score derivation** (ADR-0011): click any theme card → see raw signals (mention count, VADER compound, Ï, z-score) → normalization window + method → weights from `scoring_config` → final weighted sum. Every input has a source count badge ("14 sources").

- **Citation footnotes** (ADR-0010): every numeric claim in the Q1 thesis renders with a superscript ¹-âµ footnote that links to the source key in the L0–L4 inputs (FRED series ID, theme name, factor name). Footnotes panel at the bottom lists each citation with its value.

- **Regime inputs panel** (L7 component): the regime hero card expands to show the 6 inputs that produced the current classification (yield curve slope, HY OAS, VIX, VIX term structure, real rate, breadth) with their current values and the threshold logic.

- **Per-trade derivation** (L7 component): click any row in the Trade Ideas table → see the TradeScore math (hype momentum × weight + sentiment × weight), asset selection rationale (which `theme_assets` candidates were filtered, why this one won), and position sizing logic (HypeScore weighting + cap enforcement).

**Pattern source:** Perplexity Finance — every claim has visible provenance via superscript citations + "X sources" badges. Borrowed wholesale for the same reason: the data is the product, and the user needs to trust the data.

**Why this matters for the Q1 test deliverable:** the reviewer needs to verify "why this pick" not just "what's the pick." Without L7, the LLM output is a black box. With L7, every claim in the thesis is clickable back to a source.

## Cap Enforcement

The limits are 20% single-name / 30% sector / 35% geography on **both** sizing paths, and on both they bind on the quantity they are written about — a group cap binds on the **group total**, with no minimum member count. Two names at 20% put their shared sector at 40% against a 30% limit while neither member breaches 30%; a member-wise check never fires ([ADR-0037](docs/adrs/0037-position-limits-bind-and-the-rest-is-cash.md)).

**Whatever the limits refuse is held in cash. The book is never renormalised back to 100%** — that renormalisation is what erased every cap once already, and forcing full notional into whatever names happen to clear is exactly what a position limit exists to prevent.

| | `optimizer.optimize` (primary, [ADR-0107](docs/adrs/0107-the-optimizer-sizes-what-l5-chose.md)) | `trade_ranker.allocate_portfolio` (fallback) |
|---|---|---|
| How the caps apply | **Solver constraints.** `\|w_i\| ≤ 0.20`, `Σ\|w\|` per sector ≤ 0.30, per geo ≤ 0.35, `Σ\|w\| ≤ 1` | Post-hoc clamp, iterated to a fixed point (up to 50 passes) |
| What it returns | The best book inside the limits | *A* book inside the limits |
| Direction | Pinned: `s_i · w_i ≥ 0` | Taken from the candidate |
| When it runs | Whenever there is a measured IC and a covariance | No IC, no covariance, infeasible, solver error, or an optimal book that funds nothing — with the reason persisted to `research_recommendations.sizing_reason` |

`research_recommendations.sizing_method` records which one produced the published weights, constrained to `optimizer \| conviction`. It exists because [ADR-0053](docs/adrs/0053-the-published-book-was-sized-by-hype.md) records a book that every surface described as conviction-sized while it was in fact hype-sized, with nothing in the data to catch it.

*(This section previously documented a `≥ 3 members` guard on the group caps and a final `normalize once` step. Both were removed by ADR-0037 — the first because 2 × 20% = 40% > 30% disproves it, the second because it undid every cap above it. The prose had not caught up.)*
